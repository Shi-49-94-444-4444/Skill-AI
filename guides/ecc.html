ECC — Hệ thống Tối ưu hóa Harness, Instinct & Bảo mật cho Coding Agent

ECC (Everything Claude Code) là giải pháp tối ưu hóa toàn diện hiệu năng của agent harness: biến coding agent từ một cỗ máy sinh mã bị động thành một kỹ sư thực thụ có bản năng kiểm tra (instincts), bộ nhớ duy trì xuyên suốt (memory), hàng rào bảo mật (guardrails) và quy trình nghiên cứu trước khi code (research-first).

1. Tổng quan: Đây là gì và giải quyết vấn đề gì?

Hầu hết các lập trình viên sử dụng AI coding agent (như Claude Code, Cursor, Codex, OpenCode) ở mức độ cơ bản: chỉ gõ prompt và dựa vào system prompt mặc định của nhà cung cấp. Điều này dẫn đến các điểm nghẽn nghiêm trọng:

  • Agent "mất trí nhớ": Mỗi phiên làm việc mới phải giải thích lại toàn bộ cấu trúc dự án và quy ước nhóm.
  • Bảo mật lỏng lẻo: Agent dễ bị tấn công Prompt Injection, tự ý chạy lệnh phá hủy (như rm -rf, git push --force) hoặc rò rỉ secret key ra ngoài.
  • Vội vàng sửa code (Premature mutation): Khi gặp lỗi, agent lập tức sửa bừa mã nguồn thay vì tìm hiểu nguồn gốc vấn đề, dẫn đến sửa chỗ này làm hỏng chỗ khác.

ECC (Everything Claude Code) là một framework công phu bao bọc xung quanh harness để giải quyết tất cả các điểm yếu trên, biến agent thành một trợ lý an toàn, có trí nhớ và có kỷ luật kỹ thuật cao.

Hệ sinh thái hỗ trợ Claude Code, Codex, Cursor, Opencode, Adal...
Quy tắc ngôn ngữ Node.js, Python, Go, Kotlin, Swift, PHP
Bảo mật Hàng rào kiểm soát quyền hạn doanh nghiệp
Website công cụ ecc.tools

2. Năm tầng kiến trúc tối ưu hóa của ECC

ECC hoạt động dựa trên 5 tầng phòng thủ và năng lực bổ trợ lồng ghép chặt chẽ:

1

Tầng Kỹ năng (Skills & Commands)

Các lệnh nghiệp vụ tự động hóa cao: /database-migration, /feature-development, /add-language-rules. Giúp agent thực hiện các tác vụ kỹ thuật theo quy trình chuẩn hóa cao.

2

Tầng Bản năng phản xạ (Instincts)

Các thói quen ăn sâu vào hành vi của agent mà không cần nhắc nhở: Tự động chạy linter và type check trước khi commit, không bao giờ xóa tệp chưa được lưu trữ (untracked files), kiểm tra môi trường chạy trước khi thực thi lệnh.

3

Tầng Bộ nhớ duy trì (Persistent Memory)

Lưu trữ các quyết định kiến trúc, danh sách sự cố đã xảy ra trong quá khứ và sở thích làm việc của lập trình viên vào thư mục .claude/memory/ hoặc cơ sở dữ liệu cục bộ.

4

Tầng Hàng rào bảo mật (Guardrails & Safety)

Chặn đứng các hành vi nguy hiểm: ngăn chặn việc đọc trộm các file bí mật (.env, private keys), ngăn gọi API ra bên ngoài khi chưa được phép và kiểm soát quyền thực thi lệnh shell.

5

Tầng Nghiên cứu trước khi code (Research-First Playbook)

Bắt buộc agent phải hoàn thành giai đoạn thu thập bằng chứng, chẩn đoán nguyên nhân gốc rễ và lập kế hoạch trước khi được phép ghi đè (mutate) mã nguồn.

3. Hệ thống Bản năng (Instincts) hoạt động ra sao?

Trong ECC, "Instinct" được định nghĩa là phản xạ vô điều kiện của agent trong mọi tình huống:

Tình huống Hành vi agent thông thường Bản năng ECC (Instinct)
Gặp lỗi biên dịch hoặc test hỏng Thử sửa mã ngẫu nhiên nhiều lần đến khi hết lỗi. Dừng lại, phân tích stacktrace, cô lập ca tối thiểu (minimization) rồi mới sửa một lần duy nhất.
Cần cài đặt thư viện mới Chạy ngay npm install <package> mà không kiểm tra. Kiểm tra package.json hiện tại xem đã có thư viện tương đương chưa, kiểm tra giấy phép (license) và độ an toàn của gói.
Chuẩn bị hoàn thành tác vụ Báo "Đã xong" ngay khi sửa file xong. Tự động chạy bộ test cục bộ, kiểm tra git diff để đảm bảo không sửa nhầm các file ngoài phạm vi yêu cầu.

4. Hàng rào bảo mật (Guardrails) & Kiểm soát doanh nghiệp

Tệp .claude/rules/ecc-guardrails.md đặt ra các ranh giới bất khả xâm phạm:

Lệnh cấm tuyệt đối (Strict Deny List)
  • Không bao giờ hiển thị nội dung của các tệp nhạy cảm (.env, id_rsa, credentials.json, token đăng nhập) vào context của prompt.
  • Không tự ý chạy các lệnh phá hủy vĩnh viễn dữ liệu (rm -rf /, drop database, git reset --hard) nếu không có sự phê duyệt tường minh bằng chữ ký người dùng.
  • Không tự ý gửi dữ liệu codebase lên các endpoint bên ngoài không rõ nguồn gốc.

5. Phương pháp Research-First Playbook

Thay vì vội vàng sinh mã, ECC áp dụng quy trình 4 pha nghiên cứu nghiệm ngặt:

Pha 1: Khảo sát (Survey) Đọc cấu trúc thư mục, tệp cấu hình chính, định vị chính xác vị trí lỗi hoặc module liên quan.
Pha 2: Giả thuyết (Hypothesize) Đưa ra giả thuyết rõ ràng về nguyên nhân gốc rễ và xác định bằng chứng cần thu thập.
Pha 3: Kiểm chứng (Instrument) Chạy lệnh kiểm tra hoặc thêm log tạm thời để xác thực xem giả thuyết có đúng 100% không.
Pha 4: Can thiệp (Execute) Thực hiện thay đổi mã nguồn nhỏ nhất có thể và chạy lại bộ test hồi quy (regression test).

6. Hướng dẫn tích hợp ECC vào dự án

Bạn có thể clone và nạp cấu hình ECC cho công cụ coding agent ưa thích:

bash 
# 1. Cài đặt cấu hình ECC cho Claude Code
git clone https://github.com/affaan-m/ECC.git ~/.ecc
cp -r ~/.ecc/.claude/rules/ ./your-project/.claude/rules/

# 2. Cài đặt cấu hình cho Cursor
cp -r ~/.ecc/.cursor/rules/ ./your-project/.cursor/rules/

# 3. Kích hoạt plugin ECC qua Claude Plugin Manager
claude plugin add affaan-m/ecc
