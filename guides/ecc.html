Everything Claude Code (ECC) — Bộ khung khai phóng toàn diện cho Claude Code

Bộ khung điều phối toàn diện cho Claude Code do cộng đồng xây dựng. Biến công cụ CLI mặc định thành một kỹ sư phần mềm cao cấp tự chủ với hệ thống Bản năng (Instincts), Bộ nhớ liên phiên làm việc (Cross-session Memory) và Hàng rào bảo mật chống phá hoại mã nguồn.

affaan-m/ECC · 2.9k ★ Tác giả: Affaan Mustafa · Giấy phép MIT Mã nguồn GitHub chính thức

1. So sánh: Claude Code Mặc định vs Khi được trang bị ECC

Khía cạnh Claude Code thông thường Khi tích hợp bộ khung ECC
Bộ nhớ học tập Mất sạch kiến thức sau khi kết thúc phiên gõ lệnh (Mỗi phiên là một tờ giấy trắng). Tự động ghi lại các quyết định kỹ thuật và lỗi đã sửa vào .claude/memory/ để tái sử dụng mãi mãi.
Quy chuẩn bảo mật Có nguy cơ vô tình đọc file .env chứa secret hoặc chạy lệnh xóa rm -rf bất cẩn. Hàng rào Guardrails cứng chặn tuyệt đối việc chạm vào secrets, khóa lệnh force-push git và drop DB.
Kỷ luật kiểm thử Báo "Đã xong" ngay khi vừa sửa xong file mà chưa chạy thử test suite. Bản năng Verification-First: Bắt buộc chạy test suite, kiểm tra compile pass mới được kết thúc task.
Cơ chế tự sửa sai Lặp lại cùng một lỗi nếu gặp phải trong các module khác nhau. Cơ chế Continuous-Learning: Tự phát hiện anti-pattern và cập nhật quy tắc phòng ngừa vào project rules.

2. Kiến trúc 5 Tầng của bộ khung ECC

ECC hoạt động như một lớp vỏ bảo vệ và định hướng thông minh, bọc quanh nhân Claude Code cơ bản:

Tầng 1: Kỹ năng Thực thi (Skills Layer)

Các kịch bản tự động hóa cấp cao: khảo sát kiến trúc mã nguồn, refactor hàm lớn, sinh migration database an toàn, viết integration test.

Tầng 2: Hệ thống Bản năng (Instincts Layer)

Phản xạ tự động không cần người dùng nhắc nhở: luôn đọc kỹ file trước khi sửa (Research-First), kiểm tra linter ngay khi lưu file.

Tầng 3: Bộ nhớ Kép (Dual Memory Layer)

Phân tách rạch ròi giữa bộ nhớ làm việc ngắn hạn (Scratchpad phiên hiện tại) và kho tri thức dài hạn của cả dự án (Project Knowledge Base).

Tầng 4: Hàng rào Bảo vệ (Guardrails Layer)

Danh sách cấm bất khả xâm phạm: ngăn chặn tiết lộ token API, ngăn chặn chạy script từ domain lạ, chặn ghi đè lịch sử git.

Tầng 5: Nghiên cứu trước Thực thi (Research-First Pattern)

Ép buộc agent đọc các mối quan hệ phụ thuộc trước khi sửa bất kỳ dòng mã nào, loại bỏ hoàn toàn các lỗi breaking change bất ngờ.

3. Bảng quy chuẩn an toàn (Deny-list) của Guardrails

Đối tượng bảo vệ Hành động bị chặn cứng Lý do an toàn
Biến môi trường Đọc hoặc in nội dung các file .env*, id_rsa, *.pem. Ngăn chặn việc gửi vô tình các credential hoặc API key mật lên máy chủ LLM.
Lịch sử Git Chạy git push --force hoặc git reset --hard HEAD~N trên nhánh chính. Bảo vệ lịch sử commit của nhóm không bị ghi đè không thể phục hồi.
Hệ thống tệp Lệnh xóa đệ quy không chỉ định đường dẫn cụ thể (ví dụ rm -rf / hoặc biến rỗng). Tránh tai nạn xóa nhầm toàn bộ máy trạm của lập trình viên.

4. Cài đặt ECC cho dự án của bạn

Bash · Khởi tạo cấu hình ECC 
# Sao chép bộ khung ECC vào thư mục .claude trong dự án
git clone https://github.com/affaan-m/ECC.git /tmp/ecc
cp -r /tmp/ecc/.claude ./

# Khởi chạy Claude Code với cấu hình ECC đã nạp
claude
Sức mạnh của việc học hỏi liên tục

Mỗi khi bạn chỉ ra một lỗi sai cho Claude Code, bộ nhớ ECC sẽ tự động cập nhật vào .claude/memory/lessons.md. Kể từ giây phút đó, mọi thành viên trong team khi chạy agent đều được thừa hưởng bài học kinh nghiệm này.
