Matt Pocock Skills — Kỹ thuật phần mềm thực thụ cho Coding Agent

Bộ skill tinh gọn, có khả năng kết hợp cao do Matt Pocock (Total TypeScript) phát triển. Khắc phục 4 điểm gãy kinh điển của coding agent: lệch pha yêu cầu, agent giải thích dông dài, code sinh ra không chạy được và biến codebase thành bãi rác phức tạp.

Mục đích chính Chống Vibe Coding Ép agent theo kỷ luật kiểm thử TDD và làm rõ spec trước khi code.
Dành cho ai Lập trình viên & Tech Lead Người muốn AI tạo code chạy được ngay, dễ bảo trì lâu dài.
Thời gian làm quen ~5 Phút Chỉ cần gõ lệnh /grill-me và /tdd trong phiên chat.
Hành động cốt lõi Agent chất vấn ngược Không đoán mò — agent hỏi sâu ca biên rồi mới viết unit test.

1. Bảng đối chiếu: Vấn đề "Vibe Coding" & Giải pháp

Trào lưu "vibe coding" (gõ prompt mơ hồ rồi hy vọng AI đoán đúng ý) tạo ra ảo giác tiến độ nhanh lúc đầu, nhưng nhanh chóng dẫn đến bế tắc khi codebase phình to. Matt Pocock Skills đưa các nguyên lý công nghệ phần mềm kinh điển vào agent:

Vấn đề thường gặp Hậu quả thực tế Giải pháp bằng Skill
Agent làm sai ý bạn Code xong mới nhận ra agent hiểu sai nghiệp vụ cốt lõi. Dùng /grill-me hoặc /grill-with-docs để agent chất vấn ngược lại bạn đến tận cùng trước khi code.
Agent nói dông dài tốn token Agent suy đoán thuật ngữ của dự án, dùng 20 từ thay vì 1 từ. Tự động xây dựng bảng thuật ngữ GLOSSARY.md và ADRs (Architectural Decision Records).
Code sinh ra không chạy được Không có vòng lặp kiểm chứng (flying blind). Kỹ năng /tdd: Viết test đỏ trước, viết code xanh sau, refactor cuối cùng.
Codebase thành "đống bùn" Các module phụ thuộc chéo, kiến trúc bị vỡ. Kỹ năng /improve-codebase-architecture khảo sát các cơ hội làm sâu module (deep modules).

2. Quy trình làm việc trực quan (5 bước chuẩn mực)

Sơ đồ luồng phát triển phần mềm có kỷ luật với Coding Agent
Bước 1 Phỏng vấn làm rõ

Chạy /grill-with-docs. Agent hỏi xoáy vào các ca biên, cập nhật GLOSSARY.md.

Bước 2 Đặc tả kỹ thuật

Chạy /to-spec để tổng hợp kết quả phỏng vấn thành spec kỹ thuật hoàn chỉnh.

Bước 3 Phân rã Tickets

Chạy /to-tickets để bẻ spec thành các ticket độc lập có khai báo quan hệ phụ thuộc.

Bước 4 Triển khai TDD

Chạy /tdd cho từng ticket: Test Đỏ (Fail) → Code Xanh (Pass) → Tái cấu trúc.

Bước 5 Bảo dưỡng kiến trúc

Chạy /improve-codebase-architecture để làm sâu module và giảm phụ thuộc chéo.

3. Minh họa trực quan: Vòng lặp TDD Red-Green-Refactor

Thay vì sinh code một lần và cầu nguyện, agent vận hành theo vòng lặp kiểm chứng liên tục được kiểm soát bằng test tự động:

4. Phân loại 2 tầng kỹ năng trong hệ thống

/grill-me & /grill-with-docs — Vấn đáp ngược

Agent vào vai một Senior Architect khó tính, liên tục chất vấn ngược lại bạn về các trường hợp biên, giả định ngầm, và rủi ro mở rộng trước khi bắt đầu viết code.

/tdd — Kỷ luật Test-Driven Development

Ép buộc agent không bao giờ được viết code trước. Bắt đầu bằng việc viết bài kiểm thử đơn vị thất bại (Red), viết code tối thiểu để vượt qua (Green), rồi tái cấu trúc.

/to-spec & /to-tickets — Phân rã bài toán

Chuyển đổi cuộc phỏng vấn thành bản đặc tả kỹ thuật Markdown chuẩn mực, sau đó chia nhỏ thành các ticket làm việc độc lập có quan hệ phụ thuộc rõ ràng.

maintain-glossary — Tự động cập nhật bảng thuật ngữ

Bất cứ khi nào bạn hoặc agent đưa ra một khái niệm mới về nghiệp vụ, skill này tự động ghi nhận vào GLOSSARY.md để các phiên làm việc sau không bị lệch định nghĩa.

record-architecture-decision-records — Ghi chép ADRs

Khi có quyết định kiến trúc quan trọng (chọn thư viện, đổi cấu trúc DB), agent tự động tạo file ADR để lưu lại lý do lựa chọn và các phương án đã bị loại bỏ.

5. Bắt đầu ngay trong 3 bước

1

Cài đặt bộ skill qua npx

Tải toàn bộ bộ kỹ năng vào thư mục cấu hình của agent (hỗ trợ Claude Code, Antigravity, Cursor, Codex):

Bash · Cài đặt Matt Pocock Skills 
npx skills add mattpocock/skills
2

Khởi động phiên hỏi vặn trước khi làm tính năng mới

Thay vì đưa ra yêu cầu cụ thể, hãy mở đầu bằng lệnh phỏng vấn:

Prompt · Bắt đầu Grilling Session 
/grill-me
Tôi muốn xây dựng tính năng Giỏ hàng lưu tạm trên LocalStorage và tự động đồng bộ lên Database khi người dùng đăng nhập. Hãy chất vấn tôi để hoàn thiện spec.
3

Kích hoạt TDD để viết mã an toàn

Sau khi có ticket, chỉ định agent thực thi bằng kiểm thử tự động:

Prompt · Chạy TDD cho Ticket 
/tdd Hãy thực hiện ticket số 1: Viết hàm serialize giỏ hàng. Tuân thủ nghiêm ngặt chu trình: viết test đỏ trước, chạy thử để thấy lỗi, sau đó viết code cho pass.
Lời khuyên từ Matt Pocock

Đừng coi agent là một "máy gõ code tốc độ cao". Hãy coi nó như một lập trình viên mới vào đội ngũ: nó cần bản đặc tả rõ ràng, kiểm thử tự động để bảo đảm an toàn, và sự phản hồi liên tục thay vì những chỉ thị mơ hồ.
