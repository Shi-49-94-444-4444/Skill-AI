Matt Pocock Skills — Kỹ thuật phần mềm thực thụ cho Coding Agent

Bộ skill tinh gọn, có khả năng kết hợp cao được xây dựng bởi Matt Pocock (nhà sáng lập Total TypeScript). Mục tiêu là giải quyết 4 thất bại kinh điển của lập trình viên khi dùng AI: lệch pha yêu cầu, agent nói dông dài, code không chạy được và biến codebase thành bãi rác phức tạp.

1. Tổng quan: Đây là gì và giải quyết vấn đề gì?

Lập trình trong thời đại AI thường bị cuốn vào trào lưu "vibe coding" — yêu cầu mơ hồ, để agent tự do sinh code, sau đó mất hàng giờ sửa các lỗi logic tinh vi hoặc đối mặt với một codebase rối rắm không thể bảo trì.

Các giải pháp framework lớn (như GSD, BMAD, Spec-Kit) thường cố gắng kiểm soát toàn bộ quy trình từ đầu đến cuối, nhưng lại lấy đi quyền chủ động của kỹ sư và rất khó gỡ lỗi khi quy trình sinh lỗi. Matt Pocock Skills đi theo hướng ngược lại: cung cấp các kỹ năng nhỏ, độc lập, có thể ghép nối (composable) với bất kỳ mô hình ngôn ngữ lớn (LLM) nào và chạy trên hầu hết các agent phổ biến (Claude Code, Codex, GitHub Copilot, Gemini CLI, Cursor, Windsurf...).

2. Bốn thất bại kinh điển & Bộ giải pháp tương ứng

Hệ thống skill này được Matt Pocock đúc kết từ hàng nghìn giờ làm việc thực tế với coding agent để xử lý triệt để 4 thất bại thường gặp nhất:

Thất bại kinh điển Nguyên nhân thực tế Giải pháp bằng Skill
1. Agent làm sai ý bạn Khoảng cách giao tiếp (communication gap). Lập trình viên tưởng agent đã hiểu, nhưng thực tế yêu cầu có nhiều nhánh rẽ chưa được xác định. Dùng /grill-me (cho ý tưởng/kế hoạch) hoặc /grill-with-docs (cho code). Agent sẽ đóng vai người phỏng vấn khó tính, liên tục đặt câu hỏi đào sâu mọi nhánh quyết định trước khi gõ 1 dòng code.
2. Agent nói dông dài, tốn token Thiếu ngôn ngữ chung (Ubiquitous Language theo Domain-Driven Design). Agent phải đoán thuật ngữ của dự án nên dùng 20 từ thay vì 1 từ chuẩn. Skill /grill-with-docs tự động cập nhật GLOSSARY.md và các bản ghi quyết định kiến trúc (ADR). Khi có bảng thuật ngữ, agent suy nghĩ ít token hơn và đặt tên hàm/biến nhất quán 100%.
3. Code sinh ra không chạy được Thiếu vòng lặp phản hồi (feedback loop) tức thì. Agent sinh code mà không biết thực tế code chạy ra sao (flying blind). Skill /tdd: Bắt buộc viết test đỏ (failing test) trước, sau đó mới viết mã để test xanh (passing), rồi mới refactor. Khi gặp lỗi khó, dùng /diagnosing-bugs theo quy trình cô lập nghiệm ngặt.
4. Biến codebase thành "đống bùn" (Ball of Mud) Agent sinh code rất nhanh nhưng đẩy nhanh tốc độ hỗn loạn phần mềm (software entropy). Các module bị nông, rối ren, phụ thuộc chéo. Skill /improve-codebase-architecture quét codebase tìm cơ hội làm sâu module (deepening opportunities), xuất báo cáo HTML trực quan và hướng dẫn tái cấu trúc.

3. Phân loại: User-invoked vs Model-invoked

Một điểm kiến trúc rất thông minh của bộ skill này là sự phân định rõ ràng quyền kích hoạt:

Nguyên tắc kích hoạt

User-invoked chỉ được gọi khi bạn gõ lệnh (ví dụ /grill-me), nhiệm vụ là điều phối toàn cục. Model-invoked có thể do bạn gọi hoặc do chính agent tự động kích hoạt khi nhận thấy hoàn cảnh phù hợp. Một skill User-invoked có thể gọi các skill Model-invoked, nhưng tuyệt đối không được tự ý gọi chéo một User-invoked skill khác.

Nhóm Kỹ thuật (Engineering Skills)

User-invoked (Lập trình viên gõ) /ask-matt · /grill-with-docs · /to-spec · /to-tickets · /implement · /implement-spec · /improve-codebase-architecture · /wayfinder · /retro
Model-invoked (Agent tự động vươn tới) tdd · diagnosing-bugs · codebase-design · code-review · domain-modeling · prototype · research · pr · wizard

Nhóm Năng suất (Productivity Skills)

  • /grill-me: Phỏng vấn dồn dập về bất kỳ ý tưởng, kế hoạch hay quyết định nào ngoài code.
  • /handoff: Nén ngữ cảnh hội thoại hiện tại thành tài liệu chuyển giao (handoff document) để agent ở session sau tiếp quản liền mạch.
  • /teach: Hướng dẫn người dùng học một kỹ năng/công nghệ mới từng bước thông qua workspace thực hành.
  • /to-questionnaire: Biến một quyết định phức tạp thành bảng câu hỏi markdown cho bên liên quan điền vào.
  • /wait-what: Gọi ngay khi agent giải thích khó hiểu. Agent sẽ giải thích lại bằng tiếng Anh/Việt giản dị, dựa trên thuật ngữ của GLOSSARY.md.

4. Hướng dẫn cài đặt đa nền tảng

Bạn có thể cài đặt theo dạng plugin tự cập nhật hoặc sao chép file cấu hình cục bộ vào thư mục của agent:

1. Cài đặt cho Claude Code

bash 
claude plugin install mattpocock-skills@claude-plugins-official

2. Cài đặt cho Codex

bash 
codex plugin marketplace add mattpocock/skills
codex plugin add mattpocock-skills@mattpocock

3. Cài đặt cho Gemini CLI

bash 
gemini skills install https://github.com/mattpocock/skills.git --path skills/engineering
gemini skills install https://github.com/mattpocock/skills.git --path skills/productivity

4. Cài đặt cho Cursor, Windsurf, OpenCode hoặc bất kỳ Agent nào qua npx

bash 
npx skills@latest add mattpocock/skills -a cursor   # đổi cursor thành tên agent bạn dùng
Bước bắt buộc sau khi cài đặt

Trong cửa sổ chat của agent, hãy gõ /setup-matt-pocock-skills một lần cho mỗi repository. Lệnh này sẽ hỏi bạn issue tracker (GitHub, GitLab, file local), cách gán nhãn triage và nơi lưu các tài liệu kiến trúc.

5. Quy trình làm việc mẫu (Full Workflow)

Một chu trình phát triển tính năng chuẩn mực với Matt Pocock Skills diễn ra qua 5 giai đoạn:

1

Khởi tạo và làm rõ yêu cầu (/grill-with-docs)

Trước khi viết code, bạn chạy /grill-with-docs và mô tả ý tưởng sơ bộ. Agent sẽ phỏng vấn bạn từng khía cạnh: luồng người dùng, ca biên, cách xử lý lỗi và lưu lại các thuật ngữ mới vào GLOSSARY.md.

2

Đặc tả kỹ thuật & Phân rã công việc (/to-spec & /to-tickets)

Chạy /to-spec để tổng hợp toàn bộ nội dung phỏng vấn thành bản đặc tả kỹ thuật chi tiết. Sau đó chạy /to-tickets để bẻ spec thành các ticket nhỏ độc lập có khai báo rõ quan hệ phụ thuộc (blocking edges).

3

Triển khai bằng TDD (/implement & tdd)

Chạy /implement. Agent sẽ duyệt qua danh sách ticket, kích hoạt kỹ năng tdd tại từng điểm giao tiếp: tạo test thất bại trước, viết logic tối thiểu để vượt qua test, sau đó mới dọn dẹp mã nguồn.

4

Đánh giá mã hai trục (/code-review)

Trước khi commit, kỹ năng code-review chạy 2 sub-agent độc lập song song: một sub-agent soi xem code có bám sát Spec ban đầu không, một sub-agent soi theo Tiêu chuẩn kỹ thuật và các Code Smells của Martin Fowler.

5

Tạo Pull Request chuẩn mực (/pr)

Tự động tạo PR body gồm: tóm tắt trực quan ngắn gọn nhất, bằng chứng trước/sau (before/after) chứng minh code hoạt động và đánh giá mức độ rủi ro (One-way hay Two-way door decision).

6. Lưu ý quan trọng & Khắc phục sự cố

Tránh cài đặt trùng lặp

Nếu bạn đã cài đặt qua Plugin Manager của agent (ví dụ Claude Code plugin), đừng cài thêm qua skills.sh hoặc npx skills. Việc cài cả hai cách sẽ khiến agent nạp mọi kỹ năng 2 lần và gây xung đột context.

Tập tin GLOSSARY.md rất quan trọng

Đừng xóa hoặc sửa tay GLOSSARY.md nếu không cần thiết. Đây là "bộ nhớ chung" giúp agent tiết kiệm 30-40% lượng token phải suy luận mỗi khi bắt đầu một lượt trao đổi mới.
